- 문서 유형: Design (설계)
- 작성자: UI/UX 디자이너
- 상태: Draft v1
- 관련 문서: `docs/01-plan/features/raw_data.plan.md`

## 0. 디자인 원칙

1. **기존 SCADA 다크 톤을 그대로 상속한다.** 새 탭이라고 다른 테마를 쓰면 "딴 앱"처럼 보인다. 배경/패널/보더/타이포는
   기존 `--bg`, `--panel`, `--panel-2`, `--ink`, `--line` 토큰을 100% 재사용한다.
2. **의미색(`--ok`/`--warn`/--crit`/--offline`)은 절대 재정의하지 않는다.** 이 색들은 "설비 상태(정상/경고/알람/오프라인)"
   전용이다. 원본 데이터 탭의 "상태"(대기/완료/오류)는 같은 색 팔레트를 쓰더라도 **의미가 다르다는 것을 라벨과 아이콘으로
   구분**하고, "소스 종류"는 완전히 별도의 시각 언어(색이 아니라 문자 배지)로 표현한다 — 아래 1.3/1.4 참조.
3. **파일 기반 소스와 메타데이터 전용 소스를 화면에서 명확히 다르게 취급한다.** DB/SQL 카드에는 "실접속 없음"이
   문구가 아니라 **UI 구조 자체로** 드러나야 한다(업로드 영역/다운로드 버튼/진행률이 물리적으로 존재하지 않음).
4. **빈 상태·에러 상태는 기존 `.empty-note`, `.conn-error` 패턴을 확장**해서 쓴다 (완전히 새 컴포넌트를 만들지 않음).

## 1. 정보구조 (IA)

### 1.1 탭 위치

기존 탭 순서: `개요 · 알람 · 게이트웨이 이력`
신규 탭을 알람류(실시간 텔레메트리)와 분리해 맨 뒤에 추가한다.

```
[개요]  [알람]  [게이트웨이 이력]  |  [원본 데이터 수집]
```

- role="tablist" / role="tab" 패턴 그대로 사용 (`App.tsx`의 `.tabs`, `.tab` 클래스 재사용).
- 탭 라벨: **"원본 데이터 수집"**. 영문 병기 필요 시 탭 옆에 작은 sublabel이 아니라 `title`/`aria-label`에
  `Raw Data Collection`을 넣는 정도로 충분 (대시보드는 한국어 우선 — plan 6번 항목).
- 탭 pill(우측 작은 배지, 기존 `.tab .pill`)에는 **전체 등록 건수**를 숫자로 표시 (`.pill`에 crit 강조는 쓰지 않음 —
  이건 "알람 건수"가 아니라 단순 카운트이므로 중립 회색 유지).

### 1.2 소스 타입 5종과 그룹핑

목록/카탈로그는 "소스 타입"을 1차 축으로 필터링한다. 5종은 실동작 그룹과 메타데이터 그룹으로 나뉘지만,
사용자에게는 **하나의 통합 목록 + 필터**로 보여준다 (탭을 또 나누지 않음 — 탭 안에 탭은 UX 부채).

| 소스 타입 | 코드 | 실동작 여부 | 목록에서 주요 표시 필드 |
|---|---|---|---|
| 엑셀 | `excel` | 업로드·다운로드 실동작 | 파일명, 크기, 등록자, 등록일 |
| 워드 | `word` | 업로드·다운로드 실동작 | 파일명, 크기, 등록자, 등록일 |
| 스캔 PDF/이미지 | `scan` | 업로드·다운로드 실동작 | 파일명, 크기, 등록자, 등록일 |
| 설비 배치 | `layout` | 메타데이터 등록 (+선택적 파일) | 라인/설비/위치, (파일 있으면) 파일명 |
| DB/SQL | `db` | 메타데이터 등록만 (실접속 없음) | DB 종류, 호스트:포트, 등록자 |

필터 UI는 세그먼트 버튼(칩) 6개: `전체` + 5종. 각 칩에 1.3의 아이콘+글자 배지를 작게 붙여 시인성 확보.

### 1.3 소스 타입 "종류" 시각 언어 — 색이 아닌 배지

의미색 체계(ok/warn/crit/offline)와 충돌하지 않도록, 소스 종류는 **2~3글자 모노스페이스 코드 배지**로 표현한다
(파일 탐색기 아이콘처럼 각 타입이 고유 "글자 정체성"을 가짐). 배경은 항상 `--panel-3`, 글자색만 미묘하게 다른
중성 틴트를 써서 "장식"이 아니라 "라벨"로 읽히게 한다.

| 소스 타입 | 배지 텍스트 | 배지 틴트(다크 기준) | 비고 |
|---|---|---|---|
| 엑셀 | `XLS` | `#3fae6a` (초록 계열, --ok와는 톤을 낮춰 구분: 채도 낮은 sage) | 문서류 중 "정형표"라는 인상 |
| 워드 | `DOC` | `#4f8fd6` (블루) | |
| 스캔 PDF/이미지 | `SCN` | `#b98add` (퍼플) | 스캔=원본 그대로라는 뉘앙스 |
| 설비 배치 | `LAY` | `#d69a4f` (앰버, --warn과 톤 다름: 채도 낮음/명도 다름) | |
| DB/SQL | `SQL` | `#6b7b81` (그레이, --offline과 동일 계열이지만 "연결 안 됨"이 아니라 "메타만 있음"이라는 중립성 의도적으로 표현) | |

> 주의: `--ok`(#34c98d)와 `XLS` 배지 색, `--warn`(#ffb238)과 `LAY` 배지 색이 스포이드로 찍었을 때 구분 안 될
> 정도로 가까우면 안 된다. 위 값들은 채도/명도를 낮춰 "상태색이 아니라 라벨색"임을 무의식적으로도 구분되게 했다.
> 구현 시 CSS 변수명도 `--src-excel`, `--src-word`, `--src-scan`, `--src-layout`, `--src-db`처럼
> **`--ok/--warn`과 네이밍부터 다른 네임스페이스**를 써서 재정의 위험을 원천 차단한다.

배지 컴포넌트 형태: `PlcGrid`의 `.status-pill`과 구조는 비슷하되(둥근 pill, 12px 정사각 아이콘 없음, 텍스트만),
`::before` 점(dot) 대신 **고정폭 3글자 코드**를 쓰는 점이 다르다. 즉 `status-pill`을 상속하지 않고
`.src-badge`라는 이름으로 명확히 분리한다.

### 1.4 등록 상태 pill — 상태값의 의미와 색

원본 데이터 항목의 "상태"는 설비 건강 상태(ok/warn/crit/offline)와 무관한 **업로드/등록 라이프사이클**이다.
같은 `--ok/--warn/--crit` 색 토큰을 재사용하되(새 색을 늘리지 않기 위해), **라벨 텍스트와 문맥으로 의미를 분리**한다.

| 상태 코드 | 라벨(한글) | 적용 대상 | 색 토큰 | 아이콘/구조 |
|---|---|---|---|---|
| `uploading` | 업로드 중 | 파일 기반 3종 | `--accent` / `--accent-soft` | 진행 스피너 또는 인디케이터 바 |
| `synced` | 등록 완료 | 전체 5종 (파일: 저장 성공 / 배치·DB: 등록 성공) | `--ok` / `--ok-bg` | 점 |
| `error` | 업로드 실패 | 파일 기반 3종만 (형식 오류/서버 오류) | `--crit` / `--crit-bg` | 점 |
| `registered` | 등록됨 (고정값) | DB/SQL 전용 | `--offline`/`--offline-bg` 대신 **중립 `--ink-faint` 톤의 `--src-db` 배경** 사용 | 점 없음, 정적 텍스트 |

- DB/SQL은 plan 요구사항상 "연결 테스트/접속 성공·실패 상태를 만들지 않는다"이므로, `registered` 라벨은
  **항상 고정**이고 색도 ok/crit처럼 "성공/실패" 뉘앙스를 주지 않도록 의도적으로 중립색을 쓴다. 이건 "완료"가
  아니라 "메타데이터만 존재함"이라는 사실을 전달해야 하기 때문 — 여기서 `--ok`(초록, 성공 뉘앙스)를 쓰면
  사용자가 "DB 연결이 성공했다"고 오해할 위험이 있다. 이는 요구사항의 안전장치를 UI 레벨에서 다시 강조하는 것.
- `uploading` 상태는 클라이언트 로컬 상태(업로드 요청 진행 중)로, 서버에는 존재하지 않는 상태 — 목록에 낙관적으로
  표시했다가 성공 시 `synced`로, 실패 시 `error`로 전환.

## 2. 화면 레이아웃

### 2.1 전체 구성 (탭 진입 시)

```
┌─────────────────────────────────────────────────────────────┐
│  [요약 카운트 카드 5개 — 엑셀/워드/스캔/배치/DB]                  │
├─────────────────────────────────────────────────────────────┤
│  [+ 새 소스 등록]  (버튼 — 클릭 시 등록 패널 열림/닫힘)            │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  등록 패널 (조건부 렌더, 기본 접힘)                        │  │
│  │  소스 타입 선택 → 타입별 폼 전환                            │  │
│  └───────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│  [필터 칩: 전체 XLS DOC SCN LAY SQL]   [검색 입력]              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  등록된 원본 데이터 목록 (테이블형, PC 우선)                 │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

`main` 컨테이너(`max-width: 1240px`, 기존 패턴)를 그대로 쓴다. 새 CSS 파일을 만들지 않고 `index.css`에
섹션을 추가하는 것을 권장 (기존 프로젝트가 단일 CSS 파일 구조).

### 2.2 요약 카운트 카드 (5개)

기존 `.kpi`(top bar)와는 다른 컨텍스트이므로, `.card` 그리드를 재사용하되 사이즈를 조금 키운 요약 전용
변형(`.src-summary-card`)을 제안:

```
┌───────────────┐
│ XLS  (배지)     │
│                │
│   14           │  ← num, 24px, --ink
│   건 등록됨      │  ← --ink-faint
└───────────────┘
```

- 5개 카드를 `grid-template-columns: repeat(auto-fill, minmax(150px,1fr))`로 배치 (기존 `.grid`보다 좁은 minmax).
- 카드 좌측 상단에 1.3의 `.src-badge` 표시. 카운트 숫자는 `.num` 클래스(모노스페이스, tabular-nums) 재사용.
- 클릭 가능하게 만들어 클릭 시 하단 필터가 해당 타입으로 즉시 전환되는 것을 권장(선택 구현) — 요약과 필터의
  연결로 "몇 건 남았는지 보고 바로 그 타입만 본다"는 PM 스토리(#2) 충족.

### 2.3 소스 등록 패널

버튼(`+ 새 소스 등록`, `.tab`이 아니라 일반 primary 버튼 — `--accent` 배경의 filled 버튼, 기존에 filled 버튼이
없으므로 신규 `.btn-primary` 정의 필요: `background: var(--accent); color: var(--bg); border-radius: 8px;`)을
누르면 패널이 펼쳐진다. 패널 상단에 소스 타입 세그먼트(1.3 배지가 포함된 라디오형 버튼 그룹) → 선택에 따라
아래 폼 필드가 전환된다.

**공통 필드** (모든 타입 상단에 항상 노출):
- 소스명 (필수, text input)
- 설비/라인 태그 (선택, text input — 자유 태그, 자동완성 없음)
- 설명/비고 (선택, textarea)
- 등록자 (필수, text input — 로그인 시스템이 없다는 전제하에 수동 입력. 만약 인증이 있다면 자동 채움)

**타입별 전환 필드**:

- **엑셀/워드/스캔 (`excel`/`word`/`scan`)**: 파일 드롭존 (아래 2.4) — 다중 선택 가능. accept 속성은 타입별로
  `excel: .xlsx,.xls`, `word: .docx,.doc`, `scan: .pdf,.png,.jpg,.jpeg`.
- **설비 배치 (`layout`)**: 라인명(필수), 설비명(필수), 위치/구역 설명(선택) 텍스트 입력 3개 + "도면 파일 첨부
  (선택)" — 위 파일 드롭존을 단수 선택 모드로 재사용, 라벨만 "도면 파일(선택)"로 변경.
- **DB/SQL (`db`)**: DB 종류(select: MSSQL/Oracle/MySQL/PostgreSQL/기타), 호스트(text), 포트(text, 숫자
  검증만·연결 검증 없음), 쿼리 텍스트(textarea, monospace 폰트 — "설명용, 실행되지 않음" 안내 문구 아래 작게 표시),
  담당자(text). **이 폼에는 "연결 테스트"/"저장 후 접속 확인" 같은 버튼이 물리적으로 존재하지 않음** — 저장
  버튼 하나만 있고, 저장 즉시 상태는 `registered` 고정.
  - 폼 하단에 조용한 안내 텍스트(경고색 아님, `--ink-faint`): "이 정보는 메타데이터로만 저장되며, 실제 DB에
    접속하지 않습니다." — crit/warn 색을 쓰지 않는 이유는 이것이 "문제"가 아니라 "설계된 동작"이기 때문.

패널 하단: `취소` (ghost 버튼) / `등록` (primary 버튼, 파일 타입이면 라벨을 `업로드`로 변경).

### 2.4 파일 드롭존 컴포넌트

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│      📄  파일을 드래그하거나        │   (점선 보더, --line-strong,
│      클릭하여 선택 (다중 가능)      │    hover 시 --accent로 전환)
│      .xlsx, .xls                 │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

선택된 파일:
┌────────────────────────────────────┐
│ [XLS] 설비점검표_2026Q1.xlsx  482KB  ✕ │
│ [XLS] 라인A_점검이력.xlsx      1.2MB ✕ │
└────────────────────────────────────┘
```

- 드롭존은 `border: 1px dashed var(--line-strong)`, hover/dragover 시 `border-color: var(--accent)` +
  `background: var(--accent-soft)`.
- 선택된 파일은 리스트로 나열, 각 항목에 1.3 배지 + 파일명 + 용량 + 개별 제거(✕) 버튼.
- 업로드 실행 시 각 파일 행에 진행 상태를 인라인으로 표시 (2.6 참조).

### 2.5 등록 목록 테이블

기존 `.gw-list`/`.gw-row`(게이트웨이 이력) 패턴을 확장 적용 — grid 기반 행 목록이 이 프로젝트의 "목록" 관용구.

컬럼: `타입 배지` | `소스명 / 파일명` | `설비·라인 태그` | `등록자` | `등록일시` | `상태 pill` | `액션(다운로드/상세)`

```
┌──────┬─────────────────────┬───────────┬────────┬─────────────────┬──────────┬────────┐
│ [XLS]│ 설비점검표_2026Q1.xlsx │ LINE-A     │ 홍길동  │ 2026-08-04 14:02 │ ● 등록완료│ ⬇ 다운로드│
├──────┼─────────────────────┼───────────┼────────┼─────────────────┼──────────┼────────┤

└──────┴─────────────────────┴───────────┴────────┴─────────────────┴──────────┴────────┘
```

- 행 클릭(액션 컬럼 제외 영역) 시 상세 패널/모달 오픈 (plan 4.2-4 상세 보기).
- 파일 기반 타입만 "다운로드" 액션 노출, `layout`/`db`는 "상세보기"만 (단, `layout`에 첨부 파일이 있으면
  다운로드도 함께 노출).
- 반응형: 좁은 화면에서는 grid-template-columns를 줄이고 `설비·라인 태그`/`등록자` 컬럼을 상세보기로 이동
  (모바일 우선순위는 낮음 — 이 대시보드는 PC 운영 화면이 우선이므로 최소한의 `overflow-x: auto` 대응만).

### 2.6 필터 / 검색

목록 위 툴바:

```
[전체] [XLS] [DOC] [SCN] [LAY] [SQL]        🔍 소스명·태그 검색
```

- 칩(세그먼트 버튼)은 `.tab`과 유사하지만 다건 동시 표시가 아니라 단일 선택 토글. 선택된 칩은
  `background: var(--panel-3)`, `border-color: var(--accent)` 정도로 활성 표시.
- 검색은 클라이언트 사이드 필터링(목록이 대량이 아닐 것으로 가정, 서버 검색 API 필요 시 향후 확장)으로도
  충분 — 소스명/태그 기준 부분일치.

## 3. 상태별 화면

### 3.1 빈 상태 (Empty State)

기존 `.empty-note`(`PlcGrid`의 "아직 수신된 PLC 데이터가 없습니다…")와 동일 톤 유지:

- **전체 빈 상태** (등록 항목 0건): 목록 영역에 `.empty-note` 텍스트 —
  "아직 등록된 원본 데이터가 없습니다. 위 '+ 새 소스 등록' 버튼으로 첫 파일을 업로드하거나 소스를 등록하세요."
- **필터 결과 빈 상태** (필터/검색으로 0건): 다른 문구로 구분 —
  "선택한 조건에 맞는 항목이 없습니다. 필터를 초기화해 보세요." + `필터 초기화` 링크 버튼.
  (전체가 비어있는 것과 필터로 비어있는 것을 같은 문구로 섞으면 사용자가 "데이터 자체가 없다"고 오해할 수 있음)
- 요약 카운트 카드도 0건일 때 숫자는 `0`으로 정상 표시 (카드 자체를 숨기지 않음 — "이 타입은 아직 하나도
  없다"는 정보 자체가 유의미하므로).

### 3.2 업로드 중 (Uploading)

- 드롭존 아래 "선택된 파일" 리스트의 각 행에 진행 표시: 파일명 우측에 퍼센트 또는 인디터미넌트 바.
  ```
  [XLS] 설비점검표.xlsx  482KB  ▓▓▓▓▓▓░░░░ 62%
  ```
  - 색은 `--accent` (의미색 아님, 진행 표시이므로 accent가 적절).
- 다중 파일 업로드 시 파일별로 개별 성공/실패가 갈릴 수 있음 — 각 행이 독립적으로 `synced`/`error`로 전환.
- 업로드 중에는 등록 패널의 `등록` 버튼을 비활성화(중복 제출 방지)하고 버튼 라벨을 "업로드 중…"으로 변경.
- 목록에도 낙관적으로 `uploading` 상태의 행을 즉시 추가해 사용자가 진행 상황을 목록에서도 추적 가능하게 함
  (성공 시 실제 서버 데이터로 교체, 실패 시 `error` 행으로 전환 후 재시도 버튼 노출).

### 3.3 업로드 실패 (Error)

- 등록 패널 내: 실패한 파일 행에 인라인 에러 — 기존 `.conn-error` 스타일을 축소한 인라인 버전.
  ```
  [XLS] 손상된파일.xlsx  0KB  ⚠ 업로드 실패: 지원하지 않는 파일 형식입니다   [재시도]
  ```
  - 텍스트: `--crit`, 배경: `--crit-bg`, 아이콘 `⚠` (기존 `.offline-note::before`와 동일 관용구).
- 폼 레벨 에러(예: 필수 필드 누락, 서버 500)는 패널 상단에 `.conn-error` 그대로 재사용:
  "업로드에 실패했습니다: {서버 에러 메시지 또는 '알 수 없는 오류가 발생했습니다'}"
- 목록에서도 실패한 항목은 `error` pill로 영구 표시(사용자가 재시도하거나 항목을 삭제하기 전까지) — 실패를
  숨기지 않고 "무엇이 실패했는지" 추적 가능하게 하는 것이 PM 스토리(#2, 진행 상황 추적)의 핵심이므로.

## 4. 테마 적합성 판단

**결론: 완전히 같은 다크/라이트 토큰 세트를 그대로 쓴다.** 새로운 accent 계열을 도입하지 않는다.

이유:
- 이 탭은 "오피스 문서라서 다른 감성"을 줄 필요가 없다 — 오히려 같은 운영 대시보드 안의 한 탭이라는 일관성이
  더 중요하다 (PM이 알람 탭과 원본 데이터 탭을 오가며 "같은 시스템"이라고 느껴야 함).
- 유일하게 새로 추가되는 색은 1.3의 "소스 종류 배지" 5색뿐이며, 이들은 상태색이 아니라 순수 라벨색이므로
  채도를 의도적으로 낮춰 배경(`--panel-3`)과 어우러지게 하고, 절대 카드 좌측 보더(`.card.ok` 같은 강조 보더)
  용도로는 쓰지 않는다 — 좌측 보더 강조는 계속 상태 pill(`synced`/`error`/`uploading`) 몫으로 남긴다.
- 라이트 테마에서는 배지 색상값을 `:root[data-theme="light"]` 블록에 채도/명도를 조정한 버전으로 별도 정의
  (다크에서 쓴 pastel 톤을 라이트에 그대로 쓰면 대비가 부족해짐 — 기존 `--ok`/`--warn`도 라이트에서 어둡게
  재정의된 패턴과 동일하게 처리).
