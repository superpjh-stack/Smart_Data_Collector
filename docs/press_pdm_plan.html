광성정밀 프레스 18대 예지보전(PdM) 머신러닝 추진 계획서

프레스 기계 18대를 대상으로 고장을 사전에 예측하는 예지보전(Predictive Maintenance) ML 시스템 구축을 위한 종속·독립변수 정의, 데이터 수집·라벨링·증강 방안, 모델링 전략과 실행 로드맵을 정리한 실무 계획서입니다.
대상 설비: 프레스 18대 문서 버전: v1.0 (Draft) 작성일: 2026-08-04 목표: 계획된 정비 → 예지 정비 전환

0. 프로젝트 개요 및 목표

프레스 공정의 예기치 못한 고장(비계획 정지)은 납기 지연·품질 불량·안전사고로 직결됩니다. 본 과제는 18대 프레스에 센서와 데이터 파이프라인을 구축하고, 머신러닝으로 고장을 사전에 예측하여 정비 시점을 최적화하는 것을 목표로 합니다.

대상 설비 및 주요 고장 부위

프레스(기계식 크랭크/유압식)의 예지보전은 "무엇이 고장 나는가"를 명확히 하는 데서 출발합니다. 18대에 공통적으로 관리해야 할 핵심 고장 모드는 다음과 같습니다.

서브시스템주요 고장 모드징후(관측 가능 신호)
구동부 (크랭크·기어·베어링)베어링 마모/스폴링, 기어 치면 손상, 크랭크샤프트 편마모진동 RMS·첨도 상승, 베어링 결함주파수(BPFO/BPFI) 성분 증가, 소음
클러치·브레이크라이닝 마모, 응답지연, 공압 누설정지각도 편차 증가, 클러치 공압 강하, 체결시간 증가
슬라이드·금형(Die)금형 마모/크랙, 편심 하중, 과부하하중(톤수) 파형 변화, 음향방출(AE), 슬라이드 편차, 제품 버(burr)
유압 시스템 (유압프레스)펌프 성능저하, 밸브 고착, 실 누유, 작동유 열화토출압 맥동·저하, 유온 상승, 오일 오염도(입자수) 증가
윤활 시스템급유 부족, 라인 막힘윤활유 압력·유량 저하, 베어링 온도 상승
전동기(모터)베어링 고장, 절연열화, 부하 이상전류 신호(MCSA) 측대역, 소비전력 증가, 모터 온도
핵심 관점 — 예지보전 ML은 단일 모델이 아니라 "고장 모드별로 예측 문제를 나누어" 접근합니다. 베어링은 진동 기반 잔여수명(RUL), 금형은 하중/AE 기반 이상탐지, 유압은 압력·유온 기반 열화지수 식으로 서브시스템별 종속변수와 특징이 달라집니다.

문서 구성 안내

본 계획서는 상단 탭으로 구성됩니다 — ① 예측 대상(종속변수) 정의 → ② 입력 특징(독립변수) 설계 → ③ 데이터 수집 아키텍처 → ④ 고장데이터 확보·증강 → ⑤ ML 모델링 → ⑥ 실행 로드맵·KPI. 순서대로 읽으시면 데이터 → 모델 → 실행의 흐름으로 이어집니다.

1. 종속변수 — 무엇을 예측할 것인가

종속변수(Target/Label, Y)는 ML이 예측하려는 값입니다. 예지보전에서는 목적에 따라 아래 4가지 형태를 병행합니다. 데이터 성숙도에 따라 단계적으로 확장하는 것을 권장합니다.

예측 목표(Target)의 4가지 유형

#종속변수(Y)문제유형정의도입 우선순위
A 이상 여부 / 이상점수
Anomaly Score		 비지도 현재 상태가 정상 패턴에서 얼마나 벗어났는지 (0~1). 고장 라벨이 없어도 시작 가능. 1순위 초기 데이터로 즉시 시작
B 고장 임박 여부
Failure within N		 분류 "향후 N시간(또는 N타수) 이내 고장 발생?" 예/아니오 또는 정상/주의/위험 3단계. 2순위 라벨 축적 후
C 고장 유형(부위) 분류
Fault Classification		 다중분류 고장이 임박했다면 어느 부위인가 (베어링/클러치/금형/유압/모터…). 3순위 고장사례 확보 후
D 잔여 유효수명 (RUL)
Remaining Useful Life		 회귀 고장까지 남은 시간/타수. 정비 계획 수립에 가장 유용하나 가장 많은 데이터 필요. 4순위 Run-to-Failure 축적 후
단계적 전략 — 초기에는 고장 라벨이 거의 없으므로 A(이상탐지)로 시작해 "평소와 다름"을 잡아내고, 정비 이력과 매칭해 라벨을 쌓으면서 B→C→D로 확장합니다. 처음부터 RUL을 목표로 하면 데이터 부족으로 실패하기 쉽습니다.

종속변수를 만드는 방법 (라벨링)

Y는 저절로 생기지 않습니다. 아래 소스를 결합해 "언제/무엇이 고장 났는가"를 시계열에 정확히 표시(라벨링)해야 합니다.

① 정비이력(CMMS)·작업일지 매칭

고장/교체/수리 발생 시각·부위·원인을 센서 시계열에 타임스탬프로 정렬. 가장 중요한 라벨 원천이며, 이력 기록의 정확한 시각 기입이 핵심입니다.

② 고장/정지 이벤트 로그

PLC 알람, 비상정지, 품질 불량(버·치수 이탈) 발생 시점을 "고장 시각"으로 사용.

③ Run-to-Failure 구간 설정

정상 상태 → 고장 시점까지를 하나의 수명 구간으로 보고, 역산하여 각 시점의 RUL을 부여.

④ 상태등급 라벨 (정상/주의/위험)

고장 직전 일정 구간(예: 마지막 72시간)을 '위험', 그 앞을 '주의'로 규칙 라벨링(RUL 근사).

RUL 라벨 부여 개념 (C 유형 → D 유형 확장 시)

RUL(t) = t_고장 − t   (단위: 시간 또는 누적 타수)
상태등급 = 위험 if RUL ≤ 72h · 주의 if 72h < RUL ≤ 336h · 정상 otherwise

※ 임계값(72h/336h)은 부위별 열화 속도와 정비 리드타임에 맞춰 조정합니다. 초기엔 넉넉하게, 데이터가 쌓이면 통계적으로 재설정합니다.

정리 — 종속변수는 결국 두 축으로 요약됩니다. (1) "고장이 임박했는가"(이상탐지·분류)와 (2) "얼마나 남았는가"(RUL 회귀). 광성정밀은 A(이상탐지)+B(3단계 경보)를 1차 목표로 삼고, 데이터 축적에 따라 RUL로 고도화하는 로드맵을 권장합니다.

2. 독립변수 — 예측에 쓰는 입력 특징

독립변수(Feature, X)는 종속변수를 예측하기 위한 입력입니다. 크게 ①센서 원신호 ②공정/운전 조건 ③가공 파생특징(Feature Engineering)으로 나뉩니다. 예지보전 성능의 70~80%는 좋은 특징 설계에서 결정됩니다.

같은 진동값이라도 운전 조건이 다르면 의미가 다릅니다. 조건 변수는 "정규화 기준"이자 그 자체로 특징입니다.

2-3. 파생 특징 (Feature Engineering) — 핵심

원신호를 그대로 넣기보다, 물리적으로 의미 있는 지표로 변환합니다. 진동·하중 신호를 시간·주파수·시간-주파수 영역에서 요약합니다.

⏱ 시간영역 (Time-domain)

  • RMS (실효값) — 전체 에너지, 마모 진행에 따라 상승
  • Peak / Peak-to-Peak — 충격성 결함
  • Kurtosis(첨도) — 초기 베어링 결함에 민감
  • Crest Factor = Peak/RMS — 충격 대 에너지 비
  • Skewness, 표준편차, Shape/Impulse Factor

📈 주파수영역 (Frequency-domain)

  • FFT 대역 에너지 — 특정 밴드 파워
  • 베어링 결함주파수 BPFO·BPFI·BSF·FTF 성분
  • 기어 맞물림주파수(GMF) 및 측대역
  • 포락선 분석(Envelope) — 베어링 결함 검출 표준
  • MCSA 측대역 — 전류 스펙트럼 이상

🌊 시간-주파수 / 고급

  • Wavelet / STFT — 비정상 과도신호
  • 스펙트로그램 이미지 — CNN 입력용
  • 하중파형 형상 특징(피크각·상승기울기·면적)

📉 추세·통계 특징 (Trend)

  • 이동평균·기울기 — 열화 진행 속도
  • 정상상태 대비 편차(z-score)
  • 롤링 윈도우 통계(최근 24h vs 기준)
  • 동일 조건(품번·금형)별 정규화 값
물리기반 특징의 예 — 베어링 결함주파수
BPFO = (n/2)·f_r·(1 − (d/D)·cosφ)   // 외륜 결함
BPFI = (n/2)·f_r·(1 + (d/D)·cosφ)   // 내륜 결함

n:볼 수, f_r:회전주파수, d:볼경, D:피치경, φ:접촉각. 포락선 스펙트럼에서 이 주파수 성분이 커지면 해당 부위 결함으로 해석 → 고장 유형 분류(종속변수 C)에 직접 연결됩니다.

3. 데이터 수집 방안 — 무엇을, 어떻게 모을 것인가

모델보다 데이터가 먼저입니다. "어떤 센서를, 어디에, 어떤 속도로 붙이고, 어떻게 저장·라벨링하는가"의 파이프라인을 설계합니다. 18대 전체를 한 번에 하기보다 대표 2~3대 파일럿 → 전체 확산을 권장합니다.

수집 계층 설계 포인트

  • 고속(진동·하중·AE): 엣지에서 파형 수집 후 특징만 서버 전송(대역폭 절감), 이벤트 시 원파형(raw) 보관
  • 저속(온도·압력·조건): PLC/OPC-UA로 1~10Hz 상시 수집
  • 타발 동기: 크랭크각/엔코더로 매 타발의 하중파형을 정렬 → 스트로크 단위 분석
  • 시각 동기(NTP): 전 설비 타임스탬프 정렬 — 라벨 매칭의 생명

통신·저장 스택 (예시)

  • 프로토콜: OPC-UA / Modbus TCP / MQTT
  • 엣지: 산업용 IPC + Python/에지 SW
  • 시계열 DB: InfluxDB / TimescaleDB / 히스토리안
  • 원파형: 오브젝트 스토리지(파일) + 인덱스
  • 시각화: Grafana / 자체 대시보드

3-3. 데이터 품질·거버넌스 원칙

정합성

전 설비 시각동기(NTP), 센서 ID·설치위치 표준화, 단위 통일.

완전성

결측·통신단절 구간 표시, 센서 이상값 필터, 정상/이상 구간 태깅.

추적성

데이터-정비이력 연결키(설비ID·시각), 라벨 근거 기록, 버전관리.

파일럿 우선 접근 — 18대 중 고장이력이 많고 가동률이 높은 2~3대에 풀센서를 설치해 6~12개월 데이터를 확보하며 모델을 검증하고, 검증된 최소 센서셋을 나머지 설비로 확산하면 비용과 실패 위험을 줄일 수 있습니다.

4. 고장 데이터 확보 및 데이터 증강

예지보전의 가장 큰 난제는 "고장 데이터가 극히 적다"는 점입니다. 잘 관리된 설비일수록 고장이 드물어, 정상 99.x% : 고장 0.x%의 극심한 클래스 불균형이 발생합니다. 이를 해결하는 5가지 전략을 조합합니다.

왜 어려운가 — 고장은 드물고(희소), 부위마다 다르며(다양), 같은 고장이라도 조건에 따라 신호가 다릅니다(변동). 그래서 ①실제 확보 ②의도적 생성 ③시뮬레이션 ④증강 ⑤외부데이터 전이를 함께 씁니다.

4-1. 고장 데이터를 확보하는 5가지 경로

#방법내용특징
1과거 이력 발굴
(Historical)		기존 정비이력·알람로그·품질불량 기록을 시계열과 매칭해 과거 고장 사례를 라벨로 복원. 이미 수집 중인 데이터가 있다면 즉시 활용.저비용·즉시 단, 센서 없던 과거는 신호 부재
2Run-to-Failure 자연수집센서 설치 후, 부품을 교체 없이 고장 직전까지 운용(안전 범위 내)하며 열화 전 과정을 기록. RUL 학습의 정석 데이터.고품질 시간 소요(수개월~)
3의도적 결함 주입
(Seeded Fault)		시험 설비/예비 부품에 인위적 결함(마모 베어링, 미스얼라인, 헐거운 볼트, 마모 금형 등)을 장착해 고장 신호를 계획적으로 생성.빠름·다양 실고장과 차이 보정 필요
4물리·시뮬레이션
(Digital Twin)		베어링/기어/유압 동역학 모델, 유한요소(FEM)로 결함 조건의 신호를 합성. 실측이 어려운 고장 시나리오 보강.희소고장 보강 모델 정확도 의존
5공개 데이터 전이학습공개 벤치마크(NASA/CWRU 등)로 사전학습 후 광성정밀 데이터로 미세조정(Transfer Learning). 초기 데이터 부족 극복.콜드스타트 완화 도메인 차이 존재
참고: 대표 공개 예지보전 데이터셋 (전이학습·검증용)
  • CWRU (Case Western) 베어링 결함 진동 — 부위·크기별 표준 데이터
  • NASA IMS 베어링 Run-to-Failure — 수명 전과정 진동
  • NASA C-MAPSS / PHM Challenge — RUL 예측 표준 벤치마크
  • PRONOSTIA(FEMTO) 베어링 열화 데이터
  • MFPT, Paderborn 베어링 결함 데이터

※ 프레스 전용 공개셋은 드물어, 베어링·기어·모터 등 구성요소 단위 데이터로 부위별 모델을 사전학습하는 방식이 현실적입니다.

4-2. 데이터 증강 (Data Augmentation) 기법

확보한 소수의 고장 데이터를 물리적으로 타당한 범위에서 늘려 불균형을 완화하고 일반화를 높입니다.

① 신호 변형 (Signal-level)

시계열 자체를 물리적으로 그럴듯하게 변형

  • Jittering — 미세 노이즈 추가
  • Scaling / Amplitude warping — 진폭 변화(하중 변동 모사)
  • Time warping / Stretching — 속도(SPM) 변화 모사
  • Window slicing / Permutation
  • 부하·속도 재샘플링(order tracking) — 조건 일반화

② 오버샘플링 (Feature-level)

특징 벡터 공간에서 소수 클래스 보간 생성

  • SMOTE / Borderline-SMOTE — 소수클래스 합성
  • ADASYN — 학습 어려운 영역 집중 생성
  • 정상은 언더샘플링 병행

③ 생성모델 (Generative)

고장 신호 분포를 학습해 합성 데이터 생성

  • TimeGAN / RGAN — 시계열 전용 GAN
  • VAE — 잠재공간 기반 생성
  • Diffusion 기반 시계열 합성(최신)

④ 학습 기법으로 불균형 대응

데이터를 안 늘려도 모델단에서 보정

  • Class weight / Focal Loss — 소수클래스 가중
  • 이상탐지 프레이밍 — 정상만 학습(One-Class)
  • Threshold 조정 — 재현율(놓침 방지) 우선
증강 시 3대 원칙 — ①물리적 타당성(있을 수 없는 신호 만들지 않기) ②검증셋은 절대 증강 금지(실제 고장으로만 평가) ③데이터 누수 방지(증강 전 train/test 분리, 동일 설비·시간대가 양쪽에 섞이지 않게).

5. ML 모델링 방안

종속변수 유형별로 적합한 모델이 다릅니다. "복잡한 딥러닝"이 아니라 "데이터에 맞는 최소 모델"부터 시작해 성능을 확인하며 고도화합니다.

5-1. 종속변수별 추천 모델

예측 대상문제유형추천 모델(단계별)평가지표
A. 이상탐지비지도 ① 통계 관리도/Mahalanobis → ② Isolation Forest, One-Class SVM → ③ AutoEncoder(재구성오차), LSTM-AE Precision@경보, 오탐률, 탐지리드타임
B. 고장임박 분류분류 ① 로지스틱/RandomForest → ② XGBoost/LightGBM → ③ 1D-CNN, LSTM/GRU Recall(놓침↓), F1, PR-AUC
C. 고장유형 분류다중분류 Gradient Boosting, 1D-CNN(스펙트로그램은 2D-CNN) Macro-F1, 혼동행렬
D. RUL 예측회귀/생존 ① 열화지표+회귀 → ② 생존분석(Cox), Similarity 기반 → ③ LSTM/CNN-LSTM, Transformer RMSE, MAE, PHM Score(늦은예측 벌점↑)
모델 선택 철학 — 해석 가능한 트리계열(XGBoost/LightGBM)이 산업 시계열 특징 데이터에서 딥러닝 못지않게 강력하고, SHAP으로 "왜 경보했는지" 설명이 가능해 현장 신뢰를 얻기 좋습니다. 원파형·이미지(스펙트로그램)로 갈 때만 딥러닝(CNN/LSTM)을 씁니다.

5-2. 모델링 파이프라인

1. 전처리

→
2. 특징추출

→
3. 라벨링

→
4. 학습

임계값·경보·재학습

5-3. 검증·평가 설계 (매우 중요)

⚠ 피해야 할 함정

  • 시간 누수: 미래 데이터로 과거 예측 금지 → 반드시 시간순 분할
  • 설비 누수: 같은 설비가 train/test에 동시 존재 금지(설비단위 분할 병행)
  • 정확도의 함정: 불균형에서 Accuracy는 무의미 → PR-AUC·Recall 중심

✔ 올바른 평가

  • 탐지 리드타임: 고장 며칠 전에 경보했는가
  • 오탐(허위경보)률: 현장 신뢰의 핵심
  • 재현율 우선: 놓친 고장(FN)의 비용이 오탐보다 큼
  • 비용기반 지표: 정비비·다운타임 환산 이득

5-4. 운영(MLOps) 및 현장 적용

  • 경보 3단계(정상/주의/위험) + 근거(기여 특징) 대시보드 제공 → 정비팀 의사결정 지원
  • 사람참여(Human-in-the-loop): 경보에 대한 정비팀 피드백(맞음/오탐)을 재라벨로 축적 → 지속 개선
  • 드리프트 감시·주기적 재학습: 신소재·금형변경·계절변화에 모델 갱신
  • 설비별 개인화 + 공통모델: 18대 공통 베이스 모델 + 설비별 기준선 보정

6. 실행 로드맵 및 KPI

"센서부터 다 깔고 딥러닝"이 아니라, 데이터 파이프라인 → 이상탐지 → 분류 → RUL로 단계별 가치를 확인하며 확산합니다. 아래는 약 12개월 기준 예시 로드맵입니다.

6-1. 단계별 로드맵

단계기간(예시)주요 활동산출물 / 종속변수
Phase 0
준비		1~2개월 고장모드 분석(FMEA), 대상설비·센서 선정, 이력·데이터 현황 진단, 아키텍처 설계 센서 설치계획, 데이터 사전(Data Dictionary), 라벨 정의
Phase 1
수집구축		2~3개월 파일럿 2~3대 센서·엣지·DB 구축, 데이터 상시수집, 품질 검증, 대시보드 정상 기준 데이터셋, 실시간 모니터링
Phase 2
이상탐지		2~3개월 이상탐지 모델(A), 결함주입 시험, 과거이력 라벨화, 경보 튜닝 종속변수 A/B: 이상점수·주의/위험 경보
Phase 3
고도화		3~4개월 고장유형 분류(C), 증강·전이학습, 실고장 축적, 정비팀 피드백 루프 종속변수 C: 부위별 고장분류, 원인추정
Phase 4
확산·RUL		지속 전체 18대 확산, RUL 모델(D), MLOps·재학습 체계, ROI 검증 종속변수 D: 잔여수명, 정비계획 최적화

6-2. 성과지표(KPI) 체계

구분지표목표(예시)
모델 성능고장 예측 재현율(Recall)≥ 0.85 (놓친 고장 최소화)
허위경보율 / 탐지 리드타임오탐 ≤ 월 n건 / 리드타임 ≥ 3주
현장 성과비계획 다운타임 감소≥ 30% 감소
설비종합효율(OEE) 개선≥ 20%p 향상
긴급정비·부품비 절감≥ 25% 절감
운영 성숙도센서 가동률 / 데이터 완전성≥ 99% / 결측 ≤ 1%

6-3. 리스크 및 대응

리스크대응 방안
고장 데이터 부족이상탐지 우선 + 결함주입 + 증강 + 전이학습(Tab 4)
라벨 부정확(정비이력 시각 오류)이력 기입 표준화, PLC 알람 자동연계, 시각동기
현장 신뢰 저하(오탐)설명가능 모델(SHAP), 3단계 경보, 피드백 루프로 점진 개선
초기 투자 부담파일럿 2~3대 검증 후 최소 센서셋으로 확산
데이터/모델 드리프트드리프트 감시·주기 재학습, 설비별 기준선 관리
요약 — 광성정밀 프레스 18대 예지보전은 (1) 파일럿 설비에 진동·하중·온도·전류 중심 센서를 붙여 데이터를 모으고, (2) 이상탐지로 빠르게 가치를 증명한 뒤, (3) 결함주입·증강·전이학습으로 고장데이터 부족을 메우고, (4) 실고장이 쌓이면 고장분류·RUL로 고도화하는 순서가 가장 현실적이고 성공확률이 높습니다.
