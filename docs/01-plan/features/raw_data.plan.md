# 1차 Raw Data 수집 대시보드 — 요구사항 문서

- 문서 유형: Plan (기획)
- 작성자: PM
- 상태: Draft v1
- 관련 영역: dashboard(신규 탭), cloud-api(신규 라우터/테이블/파일 저장)

---

## 1. 목적과 배경

### 1.1 왜 필요한가

Smart Data Collector는 지금까지 PLC/OPC UA 설비에서 실시간으로 올라오는 **정형 텔레메트리**(태그값, 알람,
게이트웨이 상태)를 수집·표시하는 데 집중해 왔다. 그러나 실제 예지보전/공정 개선 프로젝트를 시작할 때는
그 이전 단계 — 즉 **공장 곳곳에 흩어진 원본(raw) 데이터를 모으는 단계**가 반드시 선행된다. 이 원본 데이터는
설비 PLC가 아니라 사람과 종이, 파일 서버, 레거시 DB에 존재한다.

- 설비 점검표, 작업표준서, 품질 성적서 → **엑셀**
- 설비 매뉴얼, 작업지시서, 보고서 → **워드**
- 오래된 도면, 수기 점검 기록, 종이 대장을 스캔한 **PDF/이미지**
- 라인/설비 배치도, 설비 리스트, 위치 좌표 등 **설비 배치 데이터**
- 기존 MES/ERP 등 레거시 시스템에서 뽑아오는 **DB/SQL 데이터**

이 데이터들은 형식도, 보관 위치도, 담당자도 제각각이라 프로젝트 초반에 "무엇이 어디에 있는지"조차
파악하기 어렵다. 그 결과 데이터 수집 진행 상황을 아무도 추적하지 못하고, 동일 자료를 중복 요청하거나
누락된 채로 다음 단계(정제/분석)로 넘어가는 문제가 반복된다.

### 1.2 기존 PLC 텔레메트리 대시보드와의 차이

| 구분 | 기존 PLC 텔레메트리 대시보드 | 1차 Raw Data 수집 대시보드 |
|---|---|---|
| 데이터 발생원 | 설비 PLC/OPC UA (기계) | 사람, 파일 서버, 레거시 DB (비정형/반정형) |
| 수집 방식 | Edge Collector가 자동·주기적으로 push | 담당자가 파일 업로드 또는 소스 메타데이터를 수동 등록 |
| 데이터 성격 | 시계열 수치, 알람 이벤트 | 문서 파일, 배치 정보, 접속 설정 |
| 목적 | 설비 상태 실시간 모니터링 | 프로젝트 초기 "데이터 수집 현황" 추적 및 원본 아카이브 |
| 갱신 빈도 | 초/분 단위 | 건별(업로드 시점), 비정기적 |

즉 이 탭은 "설비가 지금 어떤 상태인가"가 아니라 **"우리가 필요한 원본 데이터를 얼마나 확보했는가"**를
보여주는, 프로젝트 착수 단계 전용 화면이다.

### 1.3 왜 한곳에 모아야 하는가

- 담당자·부서별로 흩어진 파일을 개별 이메일/메신저로 주고받으면 버전 관리와 진행 상황 파악이 불가능하다.
- 여러 소스 타입(엑셀/워드/PDF/배치도/DB)을 하나의 화면에서 동일한 방식(소스 등록 → 상태 추적)으로 다루면,
  프로젝트 관리자가 "무엇이 남았는지"를 한눈에 파악할 수 있다.
- 이후 단계(데이터 정제, 분석, PLC 연동 설계)에서 이 원본 데이터를 다시 찾아야 할 때, 업로드 시점에
  메타데이터(소스 타입, 등록자, 등록일, 설비/라인 태그 등)를 함께 남겨두면 재탐색 비용이 크게 줄어든다.

## 2. 소스 타입별 요구사항

이번 1차 범위는 **"파일 기반 소스는 실제 업로드·저장·조회가 동작"**하고, **"접속 정보가 필요한 소스는
메타데이터 등록까지만"** 구현하는 것으로 명확히 나눈다. 실제 고객 DB나 스캐너 장비, 설비 네트워크가
없는 현재 개발 환경의 제약을 반영한 것이며, 동시에 실제 서비스에서도 접속 정보 등록과 실제 접속 시도는
분리된 단계여야 한다는 점을 반영한다.

### 2.1 엑셀 (Excel) — 실제 동작 ✅

- "수집(收集)"의 의미: 담당자가 보유한 `.xlsx`/`.xls` 파일을 대시보드에서 직접 업로드한다.
- 1차 범위:
  - 파일 업로드 (다중 선택 가능)
  - 업로드 시 메타데이터 입력: 소스명, 설비/라인 태그(선택), 설명(선택)
  - 로컬 디스크에 파일 저장 + DB에 메타데이터(파일명, 크기, 업로드자, 업로드 일시, 저장 경로) 저장
  - 목록에서 다운로드/재조회 가능
- 1차 범위 밖: 엑셀 셀 내용 파싱, 시트별 데이터 추출, 값 검증

### 2.2 워드 (Word) — 실제 동작 ✅

- "수집"의 의미: `.docx`/`.doc` 문서 파일 업로드.
- 1차 범위: 엑셀과 동일한 업로드/저장/목록 조회 흐름 (파일 타입만 다름).
- 1차 범위 밖: 문서 텍스트 추출, 목차/버전 비교

### 2.3 스캔된 종이/PDF (Scanned Paper/PDF) — 실제 동작 ✅

- "수집"의 의미: 이미 스캔되어 이미지(`.png`/`.jpg`) 또는 `.pdf` 파일로 변환된 결과물을 업로드한다.
  **스캐너 장비와의 직접 연동은 하지 않으며**, 스캔은 사용자가 별도로 수행한 뒤 결과 파일만 업로드한다.
- 1차 범위: 업로드/저장/목록 조회 (엑셀/워드와 동일한 흐름, 파일 타입만 PDF/이미지로 확장).
- 1차 범위 밖: OCR, 텍스트 인식, 스캐너 장비 API 연동, 화질 보정

### 2.4 설비 배치 데이터 (Equipment Layout) — 메타데이터 등록만 📋

- "수집"의 의미: 설비 배치도(도면 파일)나 설비 리스트를 파일로 올릴 수도 있지만, 이번 1차에서는
  **배치 정보 자체를 구조화된 메타데이터로 등록**하는 것에 초점을 둔다 (예: 라인명, 설비명, 설비 태그,
  위치/구역 설명, 비고).
  - 도면 파일 자체는 파일 업로드 기능(2.1~2.3과 동일한 업로드 컴포넌트 재사용)으로 첨부 가능하게 하되,
    도면 좌표 인식이나 자동 배치 시각화는 만들지 않는다.
- 1차 범위: 배치 항목 등록 폼(라인/설비/위치 텍스트 입력) + 목록 조회, 선택적으로 도면 파일 첨부
- 1차 범위 밖: 배치도 자동 렌더링, 좌표 기반 지도 뷰, CAD 파일 파싱

### 2.5 DB/SQL 데이터 — 연결 설정 메타데이터 등록만 📋 (실접속 금지)

- "수집"의 의미: 실제 서비스에서는 고객의 레거시 DB(MES/ERP 등)에 접속해 SQL로 데이터를 뽑아오는 것을
  뜻하지만, **이번 1차에서는 실제 고객 DB가 없으므로 접속을 절대 시도하지 않는다.**
  대신 "이런 DB에서 이런 쿼리로 데이터를 가져올 예정"이라는 **연결 설정 메타데이터**만 등록·조회한다.
- 1차 범위:
  - 등록 폼: 소스명, DB 종류(예: MSSQL/Oracle/MySQL 등 선택), 호스트/포트(텍스트, 검증 없음),
    설명용 SQL 쿼리 텍스트(실행하지 않음), 담당자, 비고
  - 목록 조회, 상태 필드(예: "등록됨" 고정값 — "연결 테스트"나 "접속 성공/실패" 같은 상태는 만들지 않는다)
- 1차 범위 밖: 실제 DB 접속/쿼리 실행, 연결 테스트(ping/handshake) 버튼, 자격증명 암호화 저장소,
  스키마 자동 조회

## 3. 사용자 스토리

1. **공장 데이터 수집 담당자**로서, 나는 보유한 설비 점검 엑셀 파일을 대시보드에 업로드하고 싶다.
   왜냐하면 이메일로 개별 전달하지 않고 프로젝트 팀 전체가 한곳에서 확인할 수 있게 하기 위해서다.
2. **프로젝트 매니저**로서, 나는 "원본 데이터 수집" 탭에서 소스 타입별로 몇 건이 등록되었는지 한눈에
   보고 싶다. 왜냐하면 어떤 데이터가 아직 안 모였는지 파악해 담당자를 독려해야 하기 때문이다.
3. **현장 엔지니어**로서, 나는 스캔한 설비 점검대장 PDF를 업로드하면서 어떤 설비/라인에 대한 것인지
   태그를 남기고 싶다. 왜냐하면 나중에 분석 담당자가 이 자료를 빠르게 찾아 쓸 수 있어야 하기 때문이다.
4. **IT/설비 담당자**로서, 나는 나중에 연동할 레거시 MES DB의 접속 정보와 쿼리 초안을 미리 등록해
   두고 싶다. 왜냐하면 실제 연동 개발 전에 어떤 소스들이 있는지 목록화해 두어야 하기 때문이다.
5. **설비 배치 담당자**로서, 나는 라인별 설비 목록과 위치 설명을 등록하고 필요하면 배치도 파일을
   함께 첨부하고 싶다. 왜냐하면 이후 대시보드에서 설비-라인 매핑 정보를 재사용해야 하기 때문이다.
6. **분석 담당자(후속 단계)**로서, 나는 등록된 원본 데이터 목록에서 소스 타입/설비 태그로 검색·필터링해
   원하는 파일을 빠르게 찾고 싶다. 왜냐하면 등록 건수가 늘어날수록 수기 탐색이 비효율적이기 때문이다.

## 4. 화면에 필요한 최소 기능 목록

### 4.1 탭 이름 제안

- **"원본 데이터 수집"** (신규 탭, 기존 "개요/알람/게이트웨이 이력" 옆에 추가)
  - 영문 라벨이 필요할 경우: `Raw Data`

### 4.2 최소 기능

1. **탭 진입 시 요약 현황**
   - 소스 타입별(엑셀/워드/스캔 PDF/설비 배치/DB-SQL) 등록 건수 카운트 카드 5개
2. **소스 등록/업로드**
   - 소스 타입 선택 (엑셀/워드/스캔 PDF/설비 배치/DB-SQL 중 택 1)
   - 파일 기반 타입(엑셀/워드/스캔 PDF, 설비 배치의 도면 첨부 포함): 파일 선택 업로드 UI, 다중 파일 지원
   - 공통 메타데이터 입력: 소스명(필수), 설비/라인 태그(선택), 설명/비고(선택), 등록자
   - DB/SQL 타입 전용 입력: DB 종류, 호스트/포트, 쿼리 텍스트(설명용)
   - 설비 배치 타입 전용 입력: 라인명, 설비명, 위치/구역 설명
3. **등록된 원본 데이터 목록**
   - 테이블/카드 형태로 전체 목록 표시: 소스 타입, 소스명, 등록자, 등록일시, (파일이면) 파일명·크기,
     설비/라인 태그
   - 소스 타입 필터, 텍스트 검색(소스명/태그 기준)
   - 파일 기반 항목은 다운로드 링크 제공
4. **상세 보기(선택, 최소 구현)**
   - 목록 항목 클릭 시 등록된 메타데이터 전체를 보여주는 패널/모달
5. **에러/빈 상태 처리**
   - 업로드 실패 시 에러 메시지 표시
   - 등록 항목이 없을 때 빈 상태(empty state) 안내 문구

## 5. 인수 조건 (Acceptance Criteria)

- [ ] 대시보드에 "원본 데이터 수집" 탭이 추가되고, 기존 탭 전환 방식(role="tablist")과 일관되게 동작한다.
- [ ] 엑셀 파일을 업로드하면 실제로 서버에 저장되고, 목록에 즉시 나타난다.
- [ ] 워드 파일을 업로드하면 실제로 서버에 저장되고, 목록에 즉시 나타난다.
- [ ] PDF/이미지(스캔 문서) 파일을 업로드하면 실제로 서버에 저장되고, 목록에 즉시 나타난다.
- [ ] 업로드된 파일은 목록에서 다운로드할 수 있다.
- [ ] 설비 배치 데이터는 라인/설비/위치 텍스트를 입력해 등록할 수 있고, 선택적으로 도면 파일을 첨부할 수 있다.
- [ ] DB/SQL 소스는 연결 메타데이터(DB 종류, 호스트/포트, 쿼리 텍스트, 설명)를 등록할 수 있으며,
      이 과정에서 실제 DB 접속을 시도하는 코드/버튼이 전혀 없다.
- [ ] 소스 타입별 등록 건수가 요약 카드에 정확히 집계되어 표시된다.
- [ ] 목록에서 소스 타입 필터와 텍스트 검색이 동작한다.
- [ ] 등록 항목이 하나도 없을 때 빈 상태 안내가 표시된다 (에러로 보이지 않아야 함).
- [ ] 업로드 실패(예: 지원하지 않는 파일 형식, 서버 오류) 시 사용자에게 명확한 에러 메시지가 표시된다.
- [ ] 신규 API는 기존 cloud-api 라우터 패턴(prefix `/도메인/v1`)을 따르고, 새 마이그레이션은
      `003_*.sql`로 추가된다.
- [ ] 업로드된 파일은 로컬 디스크에 저장되고 DB에는 메타데이터만 저장된다 (객체 스토리지 등 신규 인프라 도입 없음).

## 6. 명시적 범위 밖 (Out of Scope)
